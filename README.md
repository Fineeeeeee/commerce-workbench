# 产品业务平台

当前为 **V4 第一阶段单工作空间应用**，业务主链已经调整为：市场证据 → 产品项目 → SPU → SKU → 内容与创意 → 渠道交付 → 经营反馈。现有素材、5+12 套图、候选图、历史版本、AI 生图和后台导出仍然保留，归入“内容与创意”，不再作为系统中心。

第一阶段完整实现日化个护 / 洗护发 / 洗发水类目和版本化属性模板；其他品类不虚构规则。渠道交付与经营反馈先人工记录，不直接发布到淘宝，也不建设采购、库存、生产、财务、复杂权限或 BI。

当前能力、验收及文字服务配置以 [开发基线](docs/08-development-baseline.md) 为准。下方带日期的记录用于追溯实施过程，不能代表最新功能状态。

2026-09-16 根据业务反馈纠偏：系统名称与试点商品解耦，默认入口为工作总览；商品档案、内容制作、审核交付分别组织，辅助能力按业务用途放在次级设置中。部署与凭证说明仅在开发文档保留。当前已有功能是整体业务中的资料/内容部分，不将改名、增加总览或隐藏技术提示当成完整企业系统。下一阶段产品项目与跨环节交付方案见 [界面与实施计划](docs/05-ui-and-plan.md)。

## 启动与使用

在本项目目录运行（Node 24.15 以上的 24.x）：

```powershell
rtk npm run build
rtk npm start
```

打开 http://127.0.0.1:4380 。仅监听本机，不开放局域网或公网。依赖已安装并锁定；新检出可用 `rtk npm install --no-audit --no-fund` 安装本项目依赖，不需要全局安装。

开发模式：`rtk npm run dev`，页面 http://127.0.0.1:5178 ，后端 4380。不要同时启动两个使用同一 `.runtime` 的服务。开发启动器关闭时会停止其子进程。

1. 在市场洞察中记录一条带来源的市场证据。
2. 建立产品项目、关联证据并推进立项阶段；建立 SPU 和具体销售规格 SKU。
3. 从项目中的 SKU 进入“内容与创意”，上传真实素材并建立“淘宝日化商品图 5+12”。
4. 逐页编辑、生成候选、保存版本并审核；整套导出 ZIP 包含有序 PNG 和设计参数 JSON。
5. 回到项目记录淘宝渠道交付和 SKU 经营反馈，时间线自动保留关键业务动作。

示例运行数据只存在于本地 `.runtime/`，不随源码发布；新检出默认使用空数据库。项目不内置真实客户、企业账号或线上业务指标。

## 存储与边界

- 数据库：`.runtime/workbench.sqlite`；原图：`.runtime/assets/`；导出包：`.runtime/exports/`。整个运行目录排除于 Git。
- 备份：先停止服务，再复制整个 `.runtime` 到独立备份目录。不要只复制正在运行的 SQLite 主文件；WAL 和素材同样属于数据。
- 首版没有账号登录、团队审批身份或公网部署，不用于多人访问。审核标记表示本机使用者确认，不代表法规审查。
- 独立 worker 与用量账本已实现。文字服务尚无真实调用验证；令牌用量不等于货币结算，费用未知不会显示为零。界面不保存 Key。
- 模板保留商品原始白底，不提供自动抠图、AI 场景融合或 PSD 分层导出。这些需要下一阶段接口和模板验证。
- 构建不自动清空旧产物；测试临时目录保留于系统临时目录，遵循不自动删除文件的约定。

## 主要代码
- `apps/web/src/`：业务总览、市场洞察、产品项目、产品资料库、内容创意、渠道交付和经营反馈。
- `apps/server/`：V4 业务 API、SQLite 迁移与版本存储、图片校验及导出。
- `packages/contracts/`：严格输入约束、页面结构及共享 SVG 模板。
- `tests/workbench.test.ts`：业务与 API 集成测试。
- `scripts/`：开发启动器和显式商品导入工具；导入真实数据前需确认来源，不作为启动时的隐藏种子数据。

技术采用 React / TypeScript / Vite、Node / Fastify、SQLite 及私有文件存储，不整体复制上游项目。旧线框图保留供设计参考，不能代表当前功能。

## 公开说明

项目解决市场资料、产品规格、内容制作和交付记录分散的问题。核心流程是：导入带来源的市场证据 → 建立产品项目和 SKU → 维护商品资料 → 按模板制作并审核内容 → 导出交付包 → 记录渠道交付和经营反馈。

市场数据来自用户主动导入的 CSV，商品素材来自用户上传的本地文件，运行数据和导出文件保存在本地工作目录。模型能力只承担结构化整理、候选文案、视觉辅助检查和背景候选生成；商品事实、价格、规格、审核、状态迁移和导出资格由程序规则与人工确认控制。模型未配置时，确定性业务流程仍可运行。

当前边界：没有登录、多人权限、云端部署、自动电商采集、库存/采购/财务系统，也没有完成真实模型服务和费用结算的公开验证。项目不宣称线上用户数、企业客户、成交效果或生产环境可用性。
# 市场研究使用（2026-09-16）

进入“市场研究”下载 CSV 模板，按约定列填写真实榜单；每批 1–500 行。填写来源、平台、统计区间、指标与单位后校验预览，确认导入。批次内支持按商品、品牌或店铺搜索、按核对结论筛选，并导出当前结果。查看记录可对照疑似关联及时间证据，填写理由、依据和确认人，核对历史持续保留。

本轮未接入电商采集或模型服务；不会把首次导入、换链接或缺少历史自动判定为新品。核对人是业务填写，不是登录认证。迁移版本 1 → 2 前自动在 `.runtime/` 保存 `before-market-<uuid>.sqlite` 一致性备份；备份不含图片，完整工作空间恢复仍须保留整个 `.runtime/`。
# 后台导出使用（2026-09-16）

整套审核后点击“检查并导出整套”，系统立即保存任务并跳转“审核与交付”。在“后台导出任务”查看真实页数进度、取消排队、恢复失败导出及下载。关闭浏览器不影响后台任务；停止整个服务时执行中任务将在租约过期后恢复。`rtk npm start` 和 `rtk npm run dev` 均自动随业务服务启动一个独立执行进程，不需要另外开终端运行队列。

数据库版本 3；迁移前保存 `.runtime/before-tasks-<uuid>.sqlite`。新增六张任务表，原商品/榜单/设计稿及导出记录保留。后台临时与已完成页面在 `.runtime/task-files/`，完整备份仍须停止业务服务和 worker 后复制整个 `.runtime/`，不能只复制 SQLite。

本轮实现后台导出、幂等、租约、固定输入、逐页恢复、流式 ZIP 和前端查询。没有模型调用或费用结算；费用表预留但不写假账单。模型候选产物采用、图片引用扩展和供应商对账随真实模型接入实施，当前接口不伪装支持。

后台导出相关测试包含独立 worker 进程、提交端关闭、第 8 页恢复、文件登记失败、旧租约提交防护、版本迁移回滚和历史导出；当前类型检查和完整测试通过，浏览器控制连接失败，真实页面点击验收未完成。
