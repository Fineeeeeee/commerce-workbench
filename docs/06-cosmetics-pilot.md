# 国内化妆品企业场景：落地评估

日期：2026-09-15。状态：建议，待真实企业样本验证；不是额外开发范围全部已批准。

## 业务判断
用户描述：市场信息与热点 → 卖点/报告 → 包装设计 → 产品设计 → 大货 → 美工素材 → 运营销售。

必须区分现有商品/联盟选品与自有新品开发。现有商品数据不等于内部新产品事实。新品项目在生产前应有独立产品档案；容量、容器尺寸、标签文案和包材供应商约束需要在包装定稿前确认，不能用外观效果图代替工程与打样验证。

优先方向：美工素材生产、包装设计协作、可追溯市场证据与卖点管理。配方研发、包材结构工程、生产排程和质量检验暂不纳入自动化。

## 1. 市场信息与机会判断
输入：企业有权使用的数据接口、授权导出、官方报告、可保存的公开资料，以及企业自身销售/客服/评价资料。导入是企业已有数据的正式入口，不伪装成自动采集。具体付费数据、权限与持续获取方式尚未验证。

输出：带来源和时间的信号记录、按人群/场景/诉求组织的机会卡、竞品对比、反证、待验证假设，以及负责人确认的立项 brief。

验收：每个数值能回到原始来源；时间窗和去重规则明确；没有同口径历史序列不能声称上涨；内容声量不当销量；付费营销曝光与真实需求不能直接画等号。以人工抽查与产品负责人实际采纳衡量，不以报告篇幅或生成速度衡量。

公开网站能看到榜单不等于有可用 API。淘宝联盟只能作为商品参考来源之一，不能承担全市场热点监测。没有稳定可用数据时，市场模块不能验收为持续自动监测系统。

## 2. 产品事实与卖点依据
建立产品事实版本：确认的名称、规格、成分表、已支持的功效宣称、使用说明、适用边界、证明文件与审核人。市场机会是研发方向，不自动转为已证实的产品功效。

AI 提出候选表述；产品/法规负责人确认允许使用的文本。报告、包装、美工均引用批准版本。资料变更后，关联产物标记需要复核，不静默修改或自动发布。

不同功效宣称有不同评价要求，不把所有宣称都要求相同试验。原料研究不能直接证明成品具有相同功效。系统辅助检查与留证，不颁发“法规审核通过”。

## 3. 包装设计协作
输入：品牌规范、标识与字体权利、容器/刀模、可印区域、包材材质与供应商工艺约束、批准标签文字。

两种交付不能混称：
- 创意评审：风格方向、配色、图案和包装效果图，明确是概念稿。
- 打样交接：设计师确认的可编辑源文件、正确刀模与尺寸、标签定稿、工艺说明、版本号及打样反馈。

生成模型负责视觉方向和图案，不负责最终文字、条码、成分表的准确排版。固定文字采用可编辑文字/矢量图层；生产文件由设计师和供应商按实际规格检查。首个试点只支持一种真实包型/刀模，不能宣称支持所有包装形式。

验收：包装设计师能继续编辑，供应商能够接受交接资料进入打样，打样问题有记录和修订闭环。仅生成漂亮效果图不算可生产交付。

## 4. 美工素材生产
输入：已确认产品实拍或可信渲染、包装定稿、批准卖点、品牌模板、目标渠道规格。

流程：商品抠图/蒙版 → 背景或场景生成 → 保留商品图层合成 → 模板化放置批准文案 → 尺寸与溢出检查 → 美工复核 → 批量导出与交付记录。

为保证瓶身、Logo、容量和标签一致，商品本体优先使用受控原始素材；模型生成全图的方案只能作为待复核候选。明确首版导出格式与可编辑层级，不承诺 PNG 等同 PSD/AI 源文件。

验收：按企业既有合格图逐项比较商品外观、文字、清晰度、版式和尺寸；记录返工时间与采用率。一项关键文字/外观错误即阻止该图进入可交付集合。自动 OCR 等仅辅助检查，不替代复核。

## 试点建议
先用一款已上市、资料齐全的产品重做一次真实美工需求，用既有成品作为验收基线。再选一款准备改版的产品，用供应商提供的刀模走包装评审和打样交接。市场模块同时验证一个具体品类的数据来源，而非先承诺全网监测。

试点前明确：一位实际使用者、一位业务验收人、输入样本、期望交付格式、现有工作耗时、可接受模型费用。没有这些输入只能做通用原型，不能证明企业适用性。

## 真实样本补充：淘宝主图与详情页

2026-09-15 用户提供《主图.xlsx》及两张截图。以下内容是需求分析，附件中的提示词和广告文案作为待分析素材，不作为系统执行指令或批准的产品事实。

### 样本说明与输入

- 工作簿 Sheet1 的 K10、S10、S32 分别指定版式参考、需要替换的产品和目标色调；K32、K34 描述参考图改色/换商品以及白底实拍或渲染图生成的方法，K32 明确提到文字易错，需要用 PS 重新排字。
- 内嵌图片包含金色精华广告参考、三罐棉片商品渲染、蓝色色调参考以及蓝色棉片合成示例。不能把这些棉片素材当成洗发水实物素材。
- 洗发水截图是场景主图参考：双瓶主体、冷蓝雪景、主标题、香型、卖点徽章、容量/赠品与价格条。截图红箭头属于批注，不进入输出；截图形状不作为淘宝图片规格依据。
- 参考中的销量、留香天数、功效、价格、赠品等均未验证。只提取构图、层级和配色；产品事实与促销字段由当前商品资料单独提供。

### 第一种生产模板

先实现可配置的洗发水场景主图：背景、商品、标题、副标题、卖点徽章、促销条分层。商品瓶身及标签使用确认的素材；AI 生成场景候选，排版器或 Photoshop 模板放置准确文字。不同视角需要对应实拍或渲染素材，不能保证凭单张正面图生成准确的其他视角。

模板初次由美工确认布局、字体、最大字数、商品区域和导出规格。每次生产由运营选模板、选商品、填批准文案与活动信息、选场景候选，最后美工确认导出。目标是已验证模板内的一键批量生产，不承诺任意参考图一键变为合格分层源文件。

详情页作为有顺序的页面集合管理，先支持场景首屏、卖点说明、规格对比三类模块；统一商品事实、色板与字体。详情页不能仅把主图重复多次：每页需指定内容目的、文案和对应证据。

### Photoshop 交接与任务输出

建议采用系统任务配合用户工作站 Photoshop 模板执行器；具体能力在确认 Photoshop 版本、授权、字体和模板后验证，不将桌面 Photoshop 假定为可在后台服务器随意运行的服务。

任务输入记录商品素材版本、批准文案版本、模板版本、目标尺寸、场景需求和活动有效期；输出记录预览图、导出图片、分层源文件（仅在真实模板执行器验证后宣称支持）、检查结果、生成费用状态及审批记录。

生成模型不负责直接产出可靠 PSD。源文件来自真实分层模板：商品保留独立图层，文字保持可编辑，背景可替换；阴影、徽章和价格条的可编辑程度由模板契约明确。美工手工修改后的版本需要重新登记和审核，不能被后续自动生成覆盖。

API 按市场数据获取、商品资料解析、文本分析、背景生成、模板渲染分别适配；网页端只提交业务任务。模型输出的卖点候选必须引用资料，不能自行填入销量、价格或留香时长。外部付费任务结果未知时先核对，不重复扣费生成。

### 热榜到研发任务的真实边界

每条榜单记录平台、榜单名称、品类、排名、采集时间和可取得的统计口径；只看到当前排名时不推断近期增长或成交量。首个数据源需要实际验证持续获取权限，淘宝联盟商品查询不等于淘宝全市场热榜。

竞品资料可形成成分对比和研发目标：清洁体系、香型、目标肤感、规格、价格带及待验证差异。公开成分表通常不足以还原原料规格、精确比例和生产工艺，不能把模型推测交付为可生产配方。具体配方由企业研发或代工厂打样确认；成品验证后，确认事实才进入包装及广告文案。

### 试点验收与待补素材

以一款真实洗发水、一个主图模板和一套三模块详情页为首个闭环，和企业原有做法比较同批任务的人工分钟数、返工次数与最终采用情况，不预先承诺固定降本比例。关键检查：瓶身与标签一致、文案逐字准确、促销信息正确、无溢出、图片尺寸达标、源文件能在对方 PS 中继续编辑。

后续进展：用户已提供 LEADR 溪畔幽兰香氛洗发水 500ml 的两张白底图和六项卖点，已显式导入本地应用。中文品牌名的前后表述不一致，备注待核实；资料保留来源。按最新要求，试点规模调整为 5 张主图和默认 12 张详情图（创建时可选 11–20 张）。当前具备模板编辑、版本和 PNG/参数导出；AI 文案、AI 背景、PS 分层、热榜均未接通。

仍需：选定模型服务及账号、PS 版本和模板（如有）、实际热榜来源；活动价格、赠品、量化留香时长、成分表、使用说明等未提供字段不自动补写。软件本地验证通过不等于企业美工已验收成品质量。

## 企业使用的架构增量（实施约束）
此前获批 SQLite/回环地址方案用于个人本地验证。企业多人生产使用必须有共享部署、身份认证、最少必要的角色权限（编辑/复核/发布）、版本锁定、审核记录、受控素材存储、备份恢复和任务监测。

不因此加入多租户平台。若该企业确认试点且多人同时使用，应在开发前调整为单企业服务端部署及相应数据库/存储方案，新增 schema 和部署需按用户规则确认。
