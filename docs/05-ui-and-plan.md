# 界面与实施计划

## 界面原则

## 2026-09-16 产品定位纠偏

“先跑通出图”的实施顺序不等于全局系统定位。本轮 UI 使用中性名称“电商产品工作台”，以真实工作总览为默认入口，商品档案作为公共资料，内容制作与审核交付作为已实现业务。系统设置在次级入口，按内容辅助、市场信息、设计交接分类，仅显示实际可用状态；没有把设置页面移动到其他位置就当成有管理员权限。

当前首页只汇总已存在商品及当前商品的设计稿，不虚构项目阶段、责任人、销量或团队待办。产品资料更新后，旧设计稿的已审核状态不能计作当前已就绪。

技术信息（本地进程、数据库、Key、API、无实际调用）放 README 和接口文档；业务页面保留任务状态、版本、缺失资料，以及“暂不可用，可先手动编辑”等操作提示。执行格式 PNG 和尺寸仍属于美工需要的交付信息。

### 企业流程的下一阶段方案（待确认实施，未新增 schema）

主线以“产品项目”组织。一个项目关联市场证据、立项报告、研发目标、包装版本、生产交接资料、销售内容和运营反馈。商品/SKU 是项目中的产品资料，不能拿一个出图任务冒充整个产品项目。

| 环节 | 实际输入与交付 | 完成条件 |
| --- | --- | --- |
| 市场研究 | 有来源与时间的榜单、竞品、评论 → 机会分析与反证 | 产品负责人决定是否进入策划 |
| 产品策划 | 机会分析、目标人群与成本条件 → 产品 brief、研发目标、卖点依据 | 产品/研发确认，并记录待验证项 |
| 包装开发 | brief、容器/刀模、标签资料 → 包装方案与打样交接文件 | 设计师和供应商确认可进入打样 |
| 生产交接 | 确认样、包材规格和验收标准 → 交接资料与反馈 | 企业现有生产负责人确认；首期不重做 ERP |
| 内容制作 | 已确认商品事实、包装与实拍 → 5 张主图和多张详情图 | 文案、实物与版式审核通过 |
| 运营反馈 | 已交付素材与同口径效果数据 → 复盘及改版需求 | 反馈关联具体产品和素材版本 |

先建立产品项目与交付关系、责任人及状态推进，再接市场来源与报告；已实现内容模块挂入项目。团队身份、权限、文件共享与备份作为企业试点必要条件单独设计。不得只添菜单和空页面宣称全流程落地。

本轮仅修正界面组织及业务用语，保留现有存储与出图操作。项目/阶段/负责人/跨环节交付需要具体 schema 和大改方案经用户确认后实施。

2026-09-15 实施进展：当前正式应用四页为「整套出图」「商品与素材」「版本与交付」「服务接入」。已实现 5 张主图和默认 12 张详情图的模板编辑、版本保存、审核与 ZIP 导出。旧六页线框图保留为历史设计。实际运行方式及验证见 README。

当前优先顺序：本地商品与整套图基础 → 真实广告文案/生图模型验证 → PS 模板交接 → 独立验证热点 → 按权限接淘宝。后文旧开发顺序供历史参考，不要求先取得淘宝账号才能出图。
中文桌面业务工作台，中性背景与深青色强调。表格用于比较，图像画廊用于挑选，任务详情用于追溯。首屏优先展示当前项目和下一步可执行动作。

[可点击线框图](ui/wireframe.html) 是设计评审稿；所有商品与状态明确为示意。不调用 API，不保存业务数据，不构成初版业务应用。

## 页面结构
1. 项目：项目名称、目标、当前阶段、候选商品、待处理事项；新用户空态引导配置连接。
2. 项目商品：筛选、选择商品、侧边详情；显示来源和采集时间。
3. 分析：对比项与报告，证据在旁；数据不足不伪造结论。
4. 素材：参考图、生成条件、结果对比、采用状态；生成新版本与采用是不同动作。
5. 任务：状态、任务类型、关联商品、时间、用量；详情区给出输入/外部阶段/输出/错误。
6. 接入：供应商、环境变量引用、配置状态和分能力测试；配置完成不等于接口可用。

设计稿里的几何图形仅占位商品图片，不作为生成样例。正式系统未配置时显示真实空态，不默认填入设计稿数据。

## 开发顺序与检查点
### A：本地业务基础
- 建立项目目录、锁定依赖、建立前后端类型契约。
- 经用户批准后创建初始 SQLite schema、项目接口、任务存储和 worker。
- 实现项目、任务、连接配置元数据页面；缺少凭证显示明确空态。
- 检查项目 CRUD、字段校验、归属校验、并发领取、租约、幂等、重启行为。

### B：真实淘宝商品
- 根据用户实际可用接口固定协议、签名、字段和权限探测。
- 完成查询、加入项目、快照留存、分页与频控。
- 用官方真实返回联调；测试 fixture 脱敏且不得作为生产回退。

### C：分析与生图
- 选定分析、生图供应商，验证参考图和输出获取能力。
- 完成报告校验、素材保存、版本采用与下载。
- 明确付费联调预算；测试不确定请求、输出无效、文件保存失败。

### D：完整验收
- 浏览器跑完整项目流程、刷新和服务重启。
- 验证备份恢复、用量状态、重复提交与失败处理。
- 如果推广/订单权限获批，按真实协议追加并验证；否则交付说明明确缺口。

## 此前确认的实施决策（历史）
1. 首版为当前电脑的本地单人 Web 应用，独立业务实现；不整体 fork 上游项目。
2. 技术路线为 React/TypeScript + Node/Fastify + 独立 worker + SQLite + 私有本地文件。
3. 批准按 03-architecture 中的初始实体创建本地数据库；推广和订单实体在权限确定后另行确认。
4. 实施范围是项目、商品、分析、素材、任务和连接管理。API 真实联调取决于账号权限与供应商选择。

这些是用户全局规则要求的“大改动方案”和“数据库 schema”确认点。确认不涵盖 .env/密钥写入、CI/CD、全局依赖安装、系统配置修改、git push、删除或公开部署。

本轮用户已明确批准新的独立商品/设计稿数据库范围，批准内容记录在 AGENTS.md 与 03-architecture.md，不再次请求同一批准。
