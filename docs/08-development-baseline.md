市场“新出现”与“真正新品”不同。条码、链接、品牌标题用于寻找疑似关联，人工结论须附证据；系统没有获得淘宝全市场历史，也不能仅凭缺少记录证明新品。包装结构、配方、生产、投流和主播不属于本次验收。

## 2. 核心对象与状态

- Product 是独立商品；ProductVersion 是不可变事实快照。卖点的 provided/pending/approved 区分提供、待核实与确认；模型只获得所选的 approved 卖点及基本资料，不发送内部备注。
- Kit 归属商品；KitVersion 固定所用商品版本。页面的用途、内容、素材、卖点和审核分别管理，内容变化使审核失效。
- Job 固定设计稿、商品、页集合、素材哈希、提示词和服务配置。Task 是执行单元；文案与视觉按页，整套导出为一个带逐页检查点的任务。
- queued 可取消；领取后 running，文案返回先 saving_result；有效产物事务保存后 succeeded。明确失败为 failed，外发后结果无法确定为 needs_reconciliation。租约过期不意味着外部请求没有发生。
- Artifact 是已保存产物；候选不覆盖设计稿。显式采用校验当前版本并生成新版本。

## 3. 数据表与所有权

| 表组 | 归属与约束 |
|---|---|
| products / product_versions / assets | 素材归商品，版本组合唯一；业务接口拒绝跨商品引用 |
| kits / kit_versions / exports | 设计稿归商品；历史不可覆盖；导出锁定稿件版本 |
| market_batches / market_entries / market_reviews | 原始条目归批次；核对可跨批次关联，保留每次理由和确认人 |
| product_opportunities / opportunity_entries | 机会唯一对应一条市场证据；纳入与排除条目均保留，关键词引用纳入记录；加入项目复用 project_evidence |
| jobs / tasks / task_attempts | 工作归稿件，任务归工作，尝试归任务；租约与代次保护提交 |
| artifacts / operation_keys / usage_ledger | 产物经任务追溯到稿件；幂等作用域区分操作及资源；用量事件唯一防重复登记 |

当前 schema 为 5。V4 建立产品业务主链，V5 增加产品机会与竞品条目关系；迁移前分别生成独立 SQLite 备份并在事务内升级。这里的所有权是业务资源归属，**没有账号、角色或多租户授权**；填写确认人不等于认证身份。开放多人访问前必须另行设计、批准并验证权限及部署，不能把回环访问校验当成用户授权。

## 4. 接口契约与最小实现

严格输入定义集中在 packages/contracts；版本写入带 baseVersion。任务提交、恢复、采用带 UUID Idempotency-Key，同键同输入取回原结果，不同输入冲突。当前任务及文案端点见 [API 契约首节](04-api-contracts.md)。旧章节含历史设想，不作为开发入口。

前端编辑草稿与已保存服务器状态分开；后台任务不会覆盖草稿。候选需要刷新读取并由人选择采用。任务可离开页面继续执行，返回后查询数据库状态；页面可见时约 2 秒轮询，隐藏时约 10 秒，终态停止。

最小闭环：榜单导入 → 老品/换链接核对 → 结构化机会分析 → 可追溯关键词 → 产品机会 → 加入产品项目 → SPU/SKU → 内容与交付。产品机会只保存观察和证据，不会自动变成真实配方或已证实卖点。

## 5. 异常流

- 版本冲突返回 409，不自动覆盖或合并。复制另一设计稿的候选编号不能绕过归属检查。
- 单页文案或视觉外发前记录 dispatching。超时、断线或派发阶段崩溃，结果待核实，不自动再次付费调用；同类未决请求存在时阻止新增请求。
- 返回结果先持久化，再校验和保存候选。后续保存失败可恢复保存，不重新调用模型。截断或非法输出不能采用，用量记录仍保留。
- 人工核对记录结论、依据和确认人；不声称费用为零，也不自动重发。需要重新生成时另建任务。
- 导出按固定快照逐页落盘、校验哈希和登记；中断后恢复已完成页，ZIP 完成且登记成功才交付。
- 完整备份需要停止服务与 worker 后复制整个 .runtime，包括 SQLite、素材和产物。已有隔离目录恢复测试；没有自动备份调度和演练平台。

## 6. 基础日志

apps/server/diagnostics.ts 记录请求编号、路由模板、状态码、耗时，以及提交工作编号、执行任务编号和结果。响应 X-Request-Id 由服务生成，不信任客户端编号；前端错误可显示该编号。可按 requestId 找提交的 jobId，再按 jobId 查任务。

日志位于 .runtime/logs/YYYY-MM-DD-进程号.ndjson，仅允许固定字段，不记录正文、查询串、密钥或完整异常对象。每进程每日上限 10 MB，写入失败输出固定提示，不伪造业务成功；按用户规则不自动删除。日志不是合规审计系统，真实业务结论仍以数据库记录为准。

## 7. 按痛点添加设施

| 当前痛点 | 已采用的最小设施 | 暂不引入 |
|---|---|---|
| 导出耗时、关闭浏览器或执行中断 | SQLite 持久队列、独立 worker、租约及检查点 | Redis、额外消息代理 |
| 重复点击、版本覆盖 | 幂等记录、事务、乐观版本检查 | 通用工作流引擎 |
| 不确定的付费请求 | 不自动重发、保存返回结果、人工核对 | 未经验证的供应商重试/切换 |
| 任务状态变化 | 有界轮询，数据库为真值 | WebSocket 服务、全局状态库 |
| 排错困难 | 请求编号与固定字段日志 | 外部遥测、监控平台 |

现有队列同时执行 1 个任务，活动队列上限 50；文案每日 UTC 最多提交 20 页、单页最大输出 1000 tokens。这是试运行数量限制，**不是人民币预算上限**。令牌显示为已记录用量，货币费用未知。市场批次每次最多 500 行；数据规模增大后先量测查询和分页，再评审索引，不用缓存掩盖扫描问题。

## 8. 文字服务接入与真实验收

文字适配器为百炼北京地域 `qwen3.7-plus`，按 [官方调用协议](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions) 实现。2026-09-16 已完成一页真实调用：输入 419 Token、输出 1985 Token，候选成功持久化并由版式检查指出正文溢出。此前失败根因是误把账号 ID 当成业务空间 ID；更正后调用成功。所有输出仍由业务 schema 校验字段、长度和证据引用，结构合格也不能证明广告词真实。

图片适配器按百炼官方协议实现：[商品背景生成](https://help.aliyun.com/zh/model-studio/wanx-background-generation-api-reference)、[Qwen Image 3.0](https://help.aliyun.com/zh/model-studio/qwen-image-generation-and-editing-api-reference)、[Wan 2.7](https://help.aliyun.com/zh/model-studio/wan-image-generation-and-editing-api-reference)、[Z-Image](https://help.aliyun.com/zh/model-studio/z-image-api-reference)。四档能力固定用途，不允许业务端输入任意模型名。正式商品场景优先使用 `wanx-background-generation-v2`：系统准备 RGBA 主体、上传到与模型绑定的48小时临时存储、持久化异步任务号并轮询；`qwen-image-3.0-pro` 与 `wan2.7-image-pro` 是创意编辑候选，不保证包装逐字不变。中文商品名、规格和卖点继续由确定性模板排版；供应商结果链接有效期有限，必须立即下载到任务产物并验证静态 PNG。

需要账户持有人按 [官方获取凭证说明](https://help.aliyun.com/zh/model-studio/get-api-key) 开通北京地域工作空间，并在服务启动环境设置：

| 环境变量 | 用途 |
|---|---|
| COMMERCE_COPY_ENABLED | 值为 1 时启用文字能力 |
| COMMERCE_IMAGE_ENABLED | 值为 1 时启用图片能力 |
| COMMERCE_BAILIAN_WORKSPACE_ID | 已开通的北京工作空间 ID |
| DASHSCOPE_API_KEY | 该工作空间可用的密钥；不要发到聊天或写入代码 |

本轮没有创建或修改 .env，没有保存真实凭证。环境改变后需要重新启动服务及其 worker。配置存在只显示“待试运行”，不代表联调成功。首次只生成一页，核对账户请求记录、返回用量、文案来源、采用后的新版本及导出，随后才扩大页数。控制台当前展示的免费额度和到期时间可能变化，收费与剩余额度仍以账户记录为准。任务同时保存模型配置版本与供应商返回模型标识。

百炼模型广场可作为后续候选模型来源，但不能把任意模型名直接开放给业务端。新增或更换模型需要建立管理员维护的允许列表，逐项记录用途、地域、供应商、模型 ID、输出契约、是否思考、图片能力、额度口径和实测版本；通过契约测试与一页真实验收后才能进入可选项。第三方推理供应商的模型还需要单独核对服务条款及数据处理边界。首个闭环固定 `qwen3.7-plus`，不做自动模型路由或失败时自动切换。

可在项目目录直接执行 `powershell -NoProfile -File scripts/start-bailian.ps1`。先停止旧工作台；脚本检查端口，提示输入北京工作空间 ID 和隐藏显示的密钥，仅设置进程环境，退出时恢复原环境，不写文件或用户/系统环境变量。启动前按[官方查询模型授权接口](https://help.aliyun.com/zh/model-studio/list-model-permissions)只读检查文字及三种图片模型的推理权限，该检查不执行模型推理。启动本身不产生模型请求；凭证仍会存在服务进程内存中。若系统策略阻止脚本，不修改系统执行策略，先报告具体错误。

## 9. 验证与下一道门槛

已执行通过 `rtk npm run typecheck`、`rtk npm test`（48 项）和 `rtk npm run build`，涵盖上述归属、并发、保存恢复、未知结果、页面用途变更、日志隐私、临时上传、异步图片任务与真实 PNG/ZIP 导出。文字、`z-image-turbo` 与 `qwen-image-3.0-pro` 均已完成一页真实供应商调用。草图模型即使明确禁字仍可能生成杂字，因此只作构图参考。Qwen 编辑结果整体可用，但底部包装文字发生轻微重绘，不能作为包装保真链路。现已增加专用商品背景模型；白底自动抠图能保住当前瓶身和标签，但高对比底色可见锯齿，正式交付仍应优先使用设计师提供的透明 PNG。

2026-09-17 已真实调用一页 `wanx-background-generation-v2`：临时上传、异步任务号保存、轮询、结果下载与采用均成功。输出完整保留包装文字，但白底自动抠图在泵头和瓶身边缘产生白边；当前可作为首版和浅色场景底稿，正式交付应使用设计师透明 PNG 或另行接商品分割。设计稿版本 6 已补齐并审核 5 张主图与 12 张详情图，后台成功导出 17 张 PNG 和 ZIP；抽查尺寸为主图 1080×1080、详情图 1080×1440。下一轮提高逐页信息密度和场景质量，不再用通用生图模型反复尝试包装保真。多人上线的身份授权、部署和运维是独立门槛，需要具体设计及批准；不能凭当前单工作空间测试就宣称企业级上线。

## 10. 企业试用门槛

这些是验收条件，不是新增空模块的清单。后续每轮交付都说明解决了哪个业务风险、如何验证、仍有什么限制。

| 阶段 | 必要条件 | 当前判断 |
|---|---|---|
| 开发过程中 | 核心用例、范围及拒绝行为明确；契约、归属、版本、幂等与故障测试随实现维护 | 已有基础；本轮补页面用途变更检查，防止旧候选误用 |
| 首位业务人员试用前 | 用另一品类真实资料走完整套制作；浏览器逐项验收；文字及图片效果人工验收；失败后可继续操作 | 未完成，不能用测试替身代替 |
| 多人接入前 | 登录、服务端权限、操作人身份、关键审核责任；角色与操作权限矩阵；并发编辑冲突可理解 | 尚未实现，需要具体设计及 schema 批准，仍只监听回环地址 |
| 企业保存正式数据前 | 明确部署责任人、备份周期和保留期；独立备份介质；实际恢复演练；磁盘与 worker 异常可发现 | 有手工完整备份和隔离恢复测试；自动化及负责人未确定 |
| 付费能力扩大使用前 | 真实调用记录、费用口径、使用限制、未知结果核对方法 | 有数量限制和令牌记录，无货币硬预算和真实账单联调 |
| 每次发版前 | 类型、回归测试、生产构建、关键页面人工验收；记录版本和变更；升级备份及恢复步骤 | 已有脚本；浏览器验收仍欠缺，尚无正式发布流程 |
| 数据或任务规模增长后 | 用真实测量决定分页、索引、并发、缓存、消息代理及数据库调整 | 暂无引入额外基础设施的证据 |

权限、备份、审计与部署属于上线前必要工作，不视为可无限延期的“后续优化”。包装开发等业务扩展则须另行确认范围。每次需要用户配合时说明具体操作、影响范围和验证结果，不仅说“注册一个 Key”。
